# Life HUD v0.3 收尾任务书

## 版本

v0.3 —— Focus

当前开发分支：

`codex/v0.3`

当前状态：

v0.3 核心业务功能已基本完成。

已有能力包括：

- 统一 FocusSession
- 铁幕 / 番茄 / 自由专注
- Focus 开始 / 暂停 / 恢复 / 完成 / 中断
- 刷新恢复
- 番茄倒计时与超时继续
- 今日统计
- Focus History
- 首页 Focus 联动
- JSON 持久化
- 小屏基础适配

本阶段禁止继续扩展新的业务系统。

目标是：

> 把“已经能用的 Focus”打磨成可以正式作为 Life HUD v0.3 发布的产品功能。

---

# 一、总体目标

本次主要处理五类工作：

1. Focus 页视觉精修
2. Focus 状态切换动画
3. 交互反馈与使用质感
4. 响应式与视觉边界修复
5. 回归测试、代码清理与版本封板

原则：

> 不新增大功能，只提升完成度。

---

# 二、Focus 首页视觉精修

当前未运行状态已经具备基础结构：

- 左侧 Focus 文案
- 右侧目标输入
- 模式选择
- 番茄时长选择
- Task 关联
- 开始 Focus
- 今日统计
- History

保持现有信息架构。

禁止重新设计整个页面。

重点进行视觉精修。

## 2.1 信息层级

进一步明确：

### 一级视觉

- “现在，认真做一件事。”
- 当前 Focus 计时器
- Focus 目标

### 二级视觉

- 模式选择
- 开始 / 暂停 / 结束

### 三级视觉

- 今日统计
- History
- 模式说明
- 辅助文本

不要让所有文字和卡片拥有相同视觉权重。

---

# 三、运行态视觉

Focus 进入 RUNNING 状态后，应明显区别于普通页面。

目标：

> 页面进入一种“安静下来”的状态。

可以采用：

- 工作台背景透明度轻微变化
- 主卡片视觉层级提升
- 计时数字更加突出
- 导航与非必要信息适度弱化
- 当前目标更加明确
- 辅助文本降低存在感

禁止：

- 全屏锁死
- 强烈闪烁
- 大幅变色
- 过重的黑色遮罩
- 游戏式战斗特效

Focus 仍然属于 Life HUD 当前的清爽视觉体系。

---

# 四、计时器视觉

计时器是运行态最重要的元素。

重点检查：

- 字体尺寸
- 数字宽度稳定
- 数字变化时页面不能抖动
- 小屏不能溢出
- 小时数超过 9 后不能破坏布局
- 超过 24h 时仍应正常显示

建议使用：

```css
font-variant-numeric: tabular-nums;

或等效方案，保证数字宽度稳定。

# 五、Focus 状态动画

动画应轻量。

统一建议时长：

```
150ms - 350ms
```

避免超过 500ms 的常规 UI 动画。

---

## 5.1 开始 Focus

点击：

`开始 Focus`

后：

启动页自然过渡到运行页。

建议：

- 主内容轻微 fade
- 卡片内容位置平滑变化
- Timer 渐显
- 不使用整页刷新感

禁止突然闪屏式切换。

---

## 5.2 暂停

暂停后：

Timer 可以轻微降低视觉活跃度。

例如：

- opacity 小幅下降
- 状态文字切换
- Pause → Resume

不要停止整个页面动画后产生“页面挂了”的感觉。

---

## 5.3 恢复

恢复后：

Timer 恢复正常视觉状态。

避免夸张动画。

---

## 5.4 Focus 完成

完成后：

建议提供一个短暂的结算过渡。

例如：

```
Focus 完成01:42:36这段时间留下来了。
```

随后进入备注 / 结算区域。

动画只需要：

- 淡入
- 轻微位移

不要设计大型庆祝动画。

后续 Progression 系统会负责真正的奖励反馈。

---

# 六、番茄钟视觉

番茄模式需要明确区分三个状态：

## 正常倒计时

```
24:32
```

## 即将结束

最后 60 秒可以产生非常轻微的状态提示。

例如：

- 小标签变化
- 辅助文字变化

禁止：

- 红色警告
- 页面闪烁
- 高频动画

## 超时继续

时间归零后选择继续专注：

```
+08:32
```

必须明显表达：

> 这是超过计划时间后的额外专注。

但视觉仍应保持柔和。

---

# 七、模式选择视觉

当前：

- 铁幕
- 番茄
- 自由专注

三个模式卡片继续保留。

优化：

- hover
- selected
- focus
- disabled

四种状态。

选中状态必须明确，但不要只依赖边框颜色。

可以结合：

- 轻微背景差异
- 描边
- 阴影
- 图标 / 小标识

---

# 八、按钮交互

统一检查：

- 开始 Focus
- 暂停
- 恢复
- 完成
- 中断
- 返回 Focus
- 番茄继续
- 番茄结束

必须拥有：

```
defaulthoveractivedisabledfocus
```

状态。

避免按钮点击后没有任何即时反馈。

危险操作：

例如：

`结束并结算`

不要与普通按钮完全相同。

但也不要使用刺眼红色。

---

# 九、输入框体验

处理：

- Focus 目标
- 自定义番茄时间
- Task ID / Task 搜索
- 备注

重点：

- focus 状态
- placeholder 可读性
- 内容过长
- Enter 行为
- 空值
- 非法数字

自定义番茄时间禁止出现浏览器原生 number input 难看的上下箭头样式破坏 UI。

根据当前 UI 体系处理。

# 十、统计卡片视觉

当前已有：

- 今日累计
- Session
- 最长一次
- 模式分布

保持轻量。

不要加入图表。

优化重点：

- 数值视觉优先级
- 单位
- `<1min` 表达
- 空状态
- 0 数据状态

建议统一：

```
0min<1min1min1h 24min
```

避免出现：

```
84min
```

这类阅读体验较差的长时间表示。

---

# 十一、History 精修

History 保持目前轻量列表设计。

每条至少区分：

- 铁幕
- 番茄
- 自由专注

状态：

- 已完成
- 已中断
- 进行中

优化：

- hover
- 行间距
- 长目标截断
- 时间格式
- 时长格式
- 标签视觉

运行中的 Session 应明显但克制地标识：

```
进行中
```

禁止让用户误以为是历史完成记录。

---

# 十二、空状态

必须检查：

## 无历史

例如：

```
还没有 Focus 记录。从一次专注开始。
```

## 今日无 Focus

```
今天还没有留下专注时间。
```

## 无关联任务

不应显示异常内容。

空状态禁止出现：

- `null`
- `undefined`
- `0 records`
- 空白大卡片

---

# 十三、首页联动视觉

Today 页面已有 Focus 卡片。

继续精修。

## 未 Focus 时

展示：

```
Focus今日 1h 24min4 Sessions
```

可进入 Focus。

## Focus 运行时

首页卡片应切换为：

```
正在 Focus开发 Life HUD v0.301:24:32返回 Focus
```

运行状态应比普通统计卡更加明显。

但禁止在 Dashboard 上复制完整 Focus 页面。

---

# 十四、全局动画规范

Focus 本次新增动画应尽量统一。

推荐：

```
hover120 - 180ms普通状态切换180 - 250ms页面 / 大卡片过渡250 - 350ms
```

动画原则：

- 少
- 顺
- 有意义

禁止：

- 弹跳动画
- 高频呼吸
- 无限漂浮
- 大幅缩放
- 旋转
- 炫技式页面转场

Life HUD 当前视觉重点依然是：

> 夏日、清透、安静、轻盈。

---

# 十五、减少动态模式

支持：

```
@media (prefers-reduced-motion: reduce)
```

用户设置减少动画时：

- 去除非必要位移
- 去除复杂过渡
- 保留必要状态变化

# 十六、背景与可读性

重点检查不同壁纸下：

- 标题
- 主卡片
- History
- Timer
- 导航
- 辅助文字

当前默认壁纸偏浅蓝。

但不能让布局只适配这一张壁纸。

需要保证：

- 浅色壁纸
- 高亮区域壁纸
- 深色局部
- 人物背景

均保持基本可读性。

必要时通过：

- backdrop-filter
- 卡片透明度
- 内部遮罩
- text-shadow

等已有设计语言处理。

不要粗暴提高整体不透明度。

# 二十、跨日行为

新增明确测试：

例如：

```
23:50 开始00:20 结束
```

确认：

- Session 本身保存完整
- 今日统计逻辑行为明确
- 不发生负数
- 不重复统计
- 不因日期变化导致当前 Session 消失

如果当前统计规则是按照 Session 开始日归属：

记录到文档。

如果按实际时间切分：

同样记录到文档。

本阶段不要为了跨日统计引入复杂分析系统。

# 二十一、异常保护

测试：

- plannedMinutes = 0
- plannedMinutes < 0
- 超大 plannedMinutes
- 空 title
- 重复开始
- Session 不存在
- 已完成 Session 再次 complete
- PAUSED 状态重复 pause
- RUNNING 状态重复 resume

后端必须安全处理。

前端不能因为 API 错误直接破坏页面。
