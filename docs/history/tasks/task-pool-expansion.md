# Life HUD 任务池扩充任务书

## 目标

在不破坏现有任务池逻辑的前提下，为 Life HUD 扩充一批新的普通任务与特殊任务，并为每个任务补充 `comment / 注释` 字段。

目标：

- 普通任务总数达到 **25+**
- 特殊任务总数达到 **30+**
- 保留现有任务，不要批量覆盖或重建任务池
- 新任务应尽量避免与现有任务重复
- 普通任务继续使用 `Energy` 奖励
- 特殊任务使用少量 `EXP` 奖励
- 特殊任务 EXP 按原先设想的 `Energy // 4` 取整后填写
- 每条新增任务都补充简短注释
- 不改动与本任务无关的业务逻辑、UI、接口或奖励机制

> 注意：请先检查当前项目中任务池的真实数据结构、存储方式和初始化逻辑，再按现有实现方式补充数据，不要凭空新造一套结构。

### 普通任务说明

- `看一集番`、`玩游戏30分钟` 这类娱乐任务可以保留，Life HUD 不应只记录生产力行为。
- `写下一句话` 和 `记录今天的一件事` 虽然接近 Journal，但门槛不同，可以共存。
- `刷一道算法题` 与泛化的 `学习20分钟` 分开。
- 若某条与现有任务完全重复，则跳过该条，不创建重复项。
- 注释尽量保持一到两句话，偏生活化，不要写成严肃的系统说明书。

## 三、注释字段规范

新增任务统一补充注释字段，建议遵循：

1. 注释主要解释任务的“完成感”和生活意味，而不是重复任务名称。
2. 长度控制在一句到两句。
3. 可以稍微有人味、轻松一点，但不要写成段子库。
4. 不要把注释写成严格判定规则，除非任务本身确实需要明确边界。
5. 如果现有数据结构字段名不是 `comment`，则沿用项目当前真实字段名。
6. 如果现有任务已经存在注释风格，优先贴合项目原有风格。

## 四、已有任务冲突处理

当前任务池里已经存在类似：

- `无短视频日`
- `健身`
- `开发`
- `阅读30分钟`
- `散步20分钟`
- `骑行10km`
- `写100字日记`
- `记录一个新点子`
- 其他已有 Daily / Special 模板

因此新增时遵循：

1. **完全同义或完全重复的任务不要重复创建。**
2. 相似但完成门槛明显不同的任务允许共存，例如：
   - `骑行10km` 与 `骑行20km`
   - `写100字日记` 与 `写500字自由记录`
   - `记录一个新点子` 与 `实现一个突然冒出来的小点子`
   - `健身` 与 `做一次完整健身训练`
3. `一整天不刷短视频` 不作为新任务重复添加。若当前 `无短视频日` 仍属于普通任务，暂时保持原样，本任务不负责迁移。
4. 不要为了凑数量加入明显无意义、过于细碎、或与现有任务高度重叠的条目。

## 五、实现要求

请 Codex：

1. 找到当前 Life HUD 任务池的真实数据来源、实体结构、初始化方式或持久化逻辑。
2. 按当前项目已有风格批量加入上述任务。
3. 普通任务写入 Daily / 普通任务池，奖励字段使用 `Energy`。
4. 特殊任务写入 Special / 特殊任务池，奖励字段使用 `EXP`。
5. 特殊任务不要再写入 Energy 奖励。
6. 每条新增任务写入对应注释字段。
7. 保留现有任务 ID、顺序、兼容逻辑与已有用户数据。
8. 如果任务 ID 需要手动生成，沿用项目当前命名规则，保证唯一性。
9. 如果当前项目支持启用/停用状态，新任务默认与现有新建模板保持同样默认状态。
10. 不修改页面布局和视觉样式。
11. 不顺手重构无关模块。

## 七、这批任务的设计意图

普通任务更偏向“维持生活运转”，例如喝水、拉伸、学习、娱乐、整理和轻量记录。

特殊任务则更偏向“制造生活事件”，例如：

- 做一次平常不会做的事
- 完成一次明显突破
- 去一个新的地方
- 和某个人产生一次连接
- 留下一段以后会记得的记录
- 完成一次梦想清单里的行动
- 做一件没有生产力，但确实让今天变得更好的事

Life HUD 不只需要回答“今天完成了多少”，也应该逐渐能回答：

> **今天发生了什么？**
