### 2. “最近最喜欢的歌”正式改成「现在。」歌单

不要再做无限 `+ 添加`。

硬编码：

```
10 个 Slot
```

因为它本来表达的就是：

> 此刻最喜欢的十首歌。

数量固定反而是产品定义，不是技术限制。

每个空 Slot：

```
01＋ 添加歌曲
```

上传后变成卡片：

```
┌────────────────────┐
│ [封面]             │
│ 晴る               │
│ ヨルシカ           │
│ 04:30              │
│              01    │
└────────────────────┘
```

支持：

```
MP3
FLAC
```

上传歌曲之后后端需要真实保存音频文件，并读取尽可能多的媒体元数据：

```
title
artist
album
duration
track
embedded cover
format
```

Java 后端可以采用适合现有 Spring Boot / JDK 21 的音频 metadata 库，例如 `jaudiotagger`，不要在前端靠文件名硬猜歌曲信息。

如果标签缺失，则：

```
title → 文件名
artist → 未知艺术家
cover → 默认音乐封面
```

嵌入封面存在时提取并展示。

本版暂时不要求完整播放器，但歌曲卡片至少应该能正确展示真实上传文件的信息。若实现成本很低，可以增加浏览器原生播放 / 暂停。

### 3. 音乐需要独立于普通 NowItem

现在 `favoriteSongs[]` 如果还是普通：

```
title
subtitle
note
```

就已经不够了。

新增明确的数据结构，例如：

```
NowSong
├── slot
├── filePath
├── originalFilename
├── title
├── artist
├── album
├── durationSeconds
├── coverPath
├── format
└── uploadedAt
```

Slot 范围严格：

```
1 ~ 10
```

当前 NowState 保存当前十首歌。

创建 NowSnapshot 时，要把当时十首歌的展示元数据冻结下来，不能未来换歌以后旧快照也跟着变化。

音频实体文件是否复制一份给 Snapshot 可以根据现有存储架构决定，但旧快照至少必须继续能正确展示当时的歌曲信息和封面。

### 4. 修掉图片上传链路

现在截图里的表现：

```
选择 Dream Blue.jpg
↓
文件名显示
↓
没有预览
↓
保存后没有图片
```

这是验收失败项。

修复后必须做到：

```
选择图片
→ 立即本地预览
→ 点击保存当前状态
→ 上传服务器
→ NowState 保存 URL / path
→ 刷新页面后仍正常显示
→ 创建 Snapshot
→ Snapshot 也正常显示
```

同时支持：

```
删除图片
多张图片
重新排序先不要求
```

不要把浏览器 `<input type=file>` 的本地路径或 filename 当成已经上传完成。

统一复用现有：

```
ImageStorageService
POST /api/images
```

如果现有接口有问题，就修这个公共链路，不要给 Now 单独造第二套上传系统。
