# Life HUD v0.3 开发任务书

## 版本名称

v0.3 —— Focus / 铁幕与人性化番茄钟

## 版本定位

v0.3 的核心目标不是“新增一个番茄钟页面”，而是正式建立 Life HUD 的 Focus 专注体系。
需要把现有或规划中的：

- 铁幕
- 番茄钟
- 自由专注
  统一抽象为同一种专注行为。
  番茄钟不再是孤立计时器。
  铁幕也不再只是人工记录的一段时间。
  二者都属于：
  
  > Focus Session
  > v0.3 完成后，Life HUD 应从“展示生活状态”进一步变成能够实际参与日常工作流程的系统。

---

# 一、核心目标

完成以下四件事情：

1. 建立统一 Focus 数据模型
2. 将“铁幕时间”正式产品化
3. 重构番茄钟，使其更加自由、人性化
4. 建立统一 Focus 工作台与今日摘要
   整体体验必须符合 Life HUD 当前视觉体系。
   不得重新做成传统效率软件、企业后台或普通番茄钟 App。

---

# 二、核心设计原则

## 2.1 Focus 是一级概念

禁止分别为铁幕、番茄钟设计两套彼此独立的业务系统。
统一使用 FocusSession 表示一次专注。
模式可以不同，但底层记录一致。
建议模式：

```text
FOCUS
├── IRON_CURTAIN
├── POMODORO
└── FREE
```

---

## 2.2 计时器服务于人

不要实现“番茄钟警察”。

允许用户：

- 自定义时长
- 提前结束
- 到点后继续
- 不休息
- 跳过休息
- 暂停
- 恢复

实际工作多久，就记录多久。

计划时长与实际时长必须分开保存。

---

## 2.3 工作时界面应逐渐安静

进入 Focus 状态后：

- 降低无关视觉元素存在感
- 减少导航干扰
- 当前目标与计时器成为视觉中心
- 不需要完全锁死页面
- 不制造压迫感

关键词：

> 沉浸、克制、清晰、安静。

---

# 三、FocusSession 数据模型

建立统一 FocusSession 模型。

建议至少包含：

```
id
mode
status

title
taskId

startedAt
endedAt

plannedMinutes
actualMinutes

note
createdAt
updatedAt
```

其中：

### mode

建议：

```
IRON_CURTAIN
POMODORO
FREE
```

### status

建议：

```
RUNNING
PAUSED
COMPLETED
INTERRUPTED
```

如当前项目已有更合适的枚举规范，可按 Java / Spring Boot 项目现有风格调整。

不要机械照搬以上字段名。

---

# 四、Focus 状态逻辑

Focus Session 至少需要支持：

```
创建 ↓RUNNING ↓PAUSED ←→ RUNNING ↓COMPLETED
```

同时允许：

```
RUNNING / PAUSED ↓INTERRUPTED
```

需要保证：

- 同一时间只能存在一个正在运行的 FocusSession
- 刷新页面后不能丢失当前 Focus 状态
- 前端时间显示不能作为唯一计时依据
- 实际时间应根据后端记录时间计算
- 页面刷新后应恢复正确计时状态

不要依赖一个纯前端 `setInterval` 保存实际业务状态。

---

# 五、Focus 工作台

新增或重构统一 Focus 页面。

Focus 页面作为 v0.3 的主要入口。

建议布局：

```
Focus[ 当前目标 ]        01:32:17    IRON CURTAIN[ 暂停 ] [ 结束 ]今日 Focus：3h 26min
```

未开始时：

```
今天准备做什么？[ 输入目标 ]模式：[ 铁幕 ][ 番茄 ][ 自由专注 ][ 开始 Focus ]
```

---

# 六、铁幕模式

## 6.1 定位

铁幕是长时间、低干扰、高投入的专注模式。

不设置默认结束时间。

核心逻辑：

```
开始铁幕↓持续计时↓用户主动结束↓记录实际持续时间
```

---

## 6.2 开始铁幕

开始前允许：

- 填写本轮目标
- 可选绑定任务
- 不要求填写预计时长

例如：

```
今晚要做什么？Life HUD v0.3 Focus 页面[ 进入铁幕 ]
```

---

## 6.3 铁幕运行态

重点显示：

- 当前目标
- 已持续时间
- 当前模式
- 暂停
- 结束

可以适当弱化：

- 顶部导航
- 其他 Dashboard 信息
- 非必要按钮

不要做真正的系统级锁屏。

---

## 6.4 铁幕结束

结束时出现轻量结算。

例如：

```
铁幕结束03:12:46完成了什么？[ 可选备注 ][ 完成 ]
```

保存：

- startedAt
- endedAt
- actualMinutes
- note
- status

---

# 七、人性化番茄钟

## 7.1 预设时间

建议提供：

```
25 min45 min60 min90 min自定义
```

默认仍可以选择 25 分钟。

但不要把 25 分钟视为唯一正确答案。

---

## 7.2 番茄运行逻辑

开始后显示倒计时。

时间归零时：

禁止强制结束 Session。

提供：

```
时间到了。[ 完成本轮 ][ 继续专注 ]
```

如果选择继续：

计时器进入超时状态，例如：

```
+ 08:32
```

最终：

```
plannedMinutes = 25actualMinutes = 34
```

---

## 7.3 休息

v0.3 不需要实现复杂番茄循环系统。

允许简单提供：

```
开始休息跳过休息
```

休息暂时不必作为 FocusSession 记录。

也不需要实现：

```
4 个番茄后强制长休息自动开启下一轮复杂周期配置
```

避免过度开发。

---

# 八、自由专注

FREE 模式作为轻量入口。

用户：

- 填写目标
- 点击开始
- 正向计时
- 自己决定结束

它与铁幕逻辑类似。

但视觉和语义无需强调“铁幕仪式”。

目的是为以后普通学习、阅读、写作等行为提供通用 Focus 模式。

---

# 九、今日 Focus 摘要

在 Focus 页面或首页加入轻量摘要。

至少展示：

```
今日累计 Focus今日 Session 数最长一次 Focus
```

可进一步展示：

```
铁幕时间番茄时间自由专注时间
```

v0.3 暂时不要开发复杂统计中心。

不要加入：

- 周/月复杂图表
- 热力图
- 排行榜
- 大量 KPI
- 效率评分

这些留给后续版本。

---

# 十、Focus 历史

提供基础历史记录即可。

每条显示：

```
模式目标开始时间结束时间持续时长状态
```

例如：

```
铁幕Life HUD v0.319:12 - 22:243h 12min
```

无需在 v0.3 实现高级搜索与筛选。

---

# 十一、首页联动

首页允许展示当前 Focus 状态。

如果正在专注：

```
FocusIRON CURTAINLife HUD v0.301:42:16[ 返回 Focus ]
```

如果当前没有 Focus：

可以展示：

```
今日专注 3h 12min[ 开始 Focus ]
```

首页不要复制完整 Focus 工作台。

---

# 十二、视觉要求

严格继承 v0.2 已确定的 Life HUD 视觉体系。

保持：

- 白 / 浅色基底
- 浅蓝主题
- 壁纸背景体系
- 半透明 / 卡片层级
- 圆角
- 柔和阴影
- 空间感
- 当前已有字体与间距规范

Focus 运行态允许比普通页面更加克制。

可以适当：

- 减少卡片
- 放大数字
- 降低辅助信息透明度
- 弱化导航

但禁止另起一套 UI 风格。

---

# 十三、计时实现要求

计时必须具有可靠性。

重点检查：

## 刷新恢复

Focus 开始后刷新页面：

必须恢复正确 Session。

例如：

```
21:00 开始21:20 刷新页面恢复后应该显示约 20 分钟
```

不能重新从 0 开始。

---

## 后台时间

浏览器切换标签页后：

计时仍应正确。

不要完全依赖浏览器每秒执行一次的 interval 累加秒数。

应依据：

```
currentTime - startedAt
```

计算。

---

## 暂停

如果支持暂停，需要正确保存暂停状态。

不能把暂停时间算入实际 Focus。

实现方式由 Codex 根据当前架构设计。

---

# 十四、后端 API

根据当前项目 REST 风格设计。

建议语义：

```
POST   /api/focus/startPOST   /api/focus/{id}/pausePOST   /api/focus/{id}/resumePOST   /api/focus/{id}/completePOST   /api/focus/{id}/interruptGET    /api/focus/currentGET    /api/focus/todayGET    /api/focus/history
```

具体路径允许根据当前 Controller 风格调整。

不要为了严格匹配以上示例破坏现有 API 规范。

---

# 十五、Java 重构要求

v0.3 新增代码继续遵守当前 Java 化方向。

避免 Python → Java 直译式代码。

重点：

- 合理拆分 Controller / Service / Repository
- DTO 与 Entity 职责明确
- 使用 enum 表达状态
- 避免超长函数
- 避免 Map<String, Object> 承担核心业务模型
- 避免大量字符串判断业务状态
- 保证类名、方法名符合 Java 惯例
- 业务校验集中在 Service 层

新增模块应尽量成为后续 Java 重构的正面示范。

---

- 朝汐分析
- 专注评分
- 效率评分
- 排行榜
- 社交功能
- 大型统计中心

除非实现基础功能必须，否则不要提前开发。

# 十八、验收标准

v0.3 完成后必须能够完整走通以下场景。

### 场景 A：铁幕

```
打开 Life HUD↓进入 Focus↓输入：“开发 Life HUD v0.3”↓点击进入铁幕↓持续工作↓刷新网页↓计时正常恢复↓结束铁幕↓填写备注↓历史中出现完整记录↓今日 Focus 时间正确增加
```

---

### 场景 B：番茄钟

```
选择 25 分钟↓开始 Focus↓倒计时↓时间归零↓选择继续专注↓继续 10 分钟↓结束
```

最终记录：

```
计划：25 min实际：35 min
```

---

### 场景 C：暂停

```
开始 Focus↓10 分钟↓暂停 5 分钟↓恢复↓10 分钟↓结束
```

实际 Focus：

```
约 20 分钟
```

而不是：

```
25 分钟
```

---

# 十九、Definition of Done

v0.3 只有满足以下条件才算完成：

- Focus 已成为统一业务概念
- 铁幕可以实际每天使用
- 番茄钟不再是孤立计时器
- 刷新不会破坏当前 Session
- 暂停时间不会错误计入 Focus
- 今日累计数据可靠
- 历史记录可靠
- UI 与 v0.2 风格统一
- 桌面端正常
- 小屏布局没有明显错位
- 无明显控制台错误
- 不留下重复旧逻辑
- 新代码符合 Java 项目结构
- 不提前堆积 v0.4+ 功能

---
