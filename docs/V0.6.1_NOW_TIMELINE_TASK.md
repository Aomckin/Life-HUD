# Life HUD v0.6.1 开发任务书：让「现在。」留下具体足迹

## 1. 背景与目标

v0.5.5 已将「现在。」页面的增删类变化写入 LifeEvent，但部分事件只记录了动作或数量，没有保存被操作的具体对象。例如图片事件只写“添加了 1 张”，时间线无法知道是哪一张；歌曲替换只保存新歌，背景与快照删除也缺少被替换或删除对象的信息。

v0.6 的 Journal 已提供统一时间线和来源筛选，但 `source="now"` 当前会退化为 `SYSTEM`，也没有独立的「现在。」筛选分区。

v0.6.1 的目标是：

1. 让「现在。」产生的 LifeEvent 足以回答“具体改变了什么”。
2. 让图片与背景直接复用 Journal 的缩略图和 lightbox 展示。
3. 在 Journal 中增加独立来源分区，用户可见文案必须严格写作 `「现在。」`。
4. 兼容现有 `life-events.json`，不要求用户手动迁移存档。
5. 统一日期与日内排序方向，并为 LifeEvent 和 Now 移除操作补齐一致的确认体验。

## 2. 产品边界

### 2.1 本次记录的事实

- 歌曲添加、替换、移除。
- 歌单背景设置、替换、清除。
- 玩 / 看 / 读条目的加入与移出。
- 图片的逐张加入与移出。
- 梦想 / 方向的加入与移出。
- 阶段快照创建与删除。

### 2.2 仍然不产生事件的变化

- 阶段标题、主题、引言、正文、歌单题注等措辞编辑。
- 歌曲播放次数、备注等陈列信息编辑。
- `posX / posY / rotationDeg / zIndex` 等纯布局重排。

这些边界延续 v0.5.5：时间线记录生活事实，不记录每一次排版或文字润色。

## 3. LifeEvent 数据契约

### 3.1 来源类型

- 新增稳定来源 `LifeEventSourceType.NOW`。
- 新事件继续保存 `source="now"`，同时序列化为 `sourceType="NOW"`。
- 读取旧事件时，若 `source="now"` 且旧 `sourceType` 为 `SYSTEM`，应归一化为 `NOW`。
- 真正的 `SYSTEM` 事件不得进入「现在。」分区。

### 3.2 通用元数据原则

- metadata 只保存可持久化的标量、列表或 Map，不保存领域对象实例。
- 图片类媒体统一写入 `metadata.images`，供 TimelineService 转换为 `TimelineItem.media`。
- 新增/移除应保存动作 `action=ADDED|REMOVED`；替换应同时保存 before 与 after。
- 事件 description 必须是无需解释 metadata 也可读懂的中文句子。

### 3.3 各类事实

- 图片：按具体路径计算差异，每张图片一个事件；metadata 保存 `imagePath` 与 `images=[imagePath]`。
- 阶段条目：保存 `category=GAME|ANIME|BOOK`、`verb`、标题，以及当时的副标题和备注。
- 歌曲：保存槽位、标题、艺术家、专辑、音频路径、封面；替换事件保存 before/after，移除事件保存被移除歌曲。
- 背景：保存旧路径与新路径；媒体优先展示与该动作最相关的图片。
- 方向：保存 `directionType=DREAM|GOAL`、对象 ID、标题及动作。
- 快照：创建和删除均保存 snapshotId、阶段标题；删除必须在 repository 删除前读取快照。

## 4. Journal 时间线

- TimelineService 新增 `now` 来源组，映射到 `LifeEventSourceType.NOW`。
- Journal 筛选栏新增 `sources=now` 标签。
- 标签和事件来源的用户可见文案均严格为 `「现在。」`，禁止显示为“现在”或英文 Now。
- 继续复用现有按天分组、缩略图、lightbox、长文折叠与分页交互。
- “全部”仍包含「现在。」事件，独立分区不复制或重写事件。
- 日期分组和同一天内的事件均按 `occurredAt` 倒序，越往下离现在越远。
- 非 JOURNAL LifeEvent 提供单独删除入口，确认后只移除事件，不反向撤销来源业务记录；JOURNAL 仍复用日记删除链路。

## 4.1 Now 与 Life 交互修整

- Now 的玩 / 看 / 读条目、已保存图片、待上传图片、歌曲、歌单背景和阶段快照在移除前统一复用 Dreams 的确认弹窗。
- Life 页面在宽屏布局下占满内容栅格，避免主内容被压成窄列。
- “最近状态”和“快速记录”卡片补充内边距与标题间距，避免文字贴边。

## 5. 兼容与安全

- 不批量改写用户的 `data/life-events.json`。
- 兼容逻辑放在 LifeEvent 读取归一化边界，使旧事件自然参与新筛选。
- 不因时间线删除展示而物理删除上传文件；历史事件引用的图片应继续可见。
- 单独删除 LifeEvent 不撤销或删除其来源业务记录。
- 开发与测试使用临时目录，不覆盖项目内真实存档。

## 6. 测试与验收

### 6.1 自动化测试

- NowService：逐张图片增删、阶段条目详情、歌曲 before/after、背景路径、方向详情、快照删除前信息。
- TimelineService：`sources=now` 隔离、NOW 标签、图片 media、旧 `SYSTEM + source=now` 归一化。
- LifeEvent API：删除成功返回 204，不存在的 ID 返回 404。
- 回归：原有 Focus、Growth、Direction、Life、Journal 测试全部通过。

### 6.2 页面验收

1. 在「现在。」加入并移除一张图片，Journal 能看到具体缩略图。
2. 替换歌曲后，事件能说明旧歌与新歌。
3. 设置、替换、清除背景后，事件保留具体背景。
4. 玩 / 看 / 读与梦想 / 方向的增删均显示具体名称。
5. Journal 的 `「现在。」` 分区只出现 Now 事件，“全部”中仍能看到同一批事件。
6. 桌面与窄屏下筛选栏可用，无明显溢出或错位。
7. 同一天内最新事件在上，日期和日内排序方向一致。
8. LifeEvent 与 Now 各移除入口在实际删除前显示统一确认弹窗。
